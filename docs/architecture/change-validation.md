# 변경 단계 검증

릴리스 때 처음 통합 문제를 발견하지 않도록 관련 변경의 PR과 main push에 한정해 아래 검사를 실행한다. 문서나 화면만 바꾼 경우 이 검사들은 실행하지 않는다. 기존 PR 전체 검증과 릴리스 최종 검증은 유지한다.

| 변경 | 실행되는 검사 |
| --- | --- |
| 서버, 저장 클라이언트, 저장 진입점, 테스트 설정 또는 의존성 | Windows와 Linux, Node 24에서 저장 충돌, 외부 편집 HTTP, 감시 경로, V3 에셋 증분 검사와 신규 캐릭터 저장 테스트 |
| 의존성, 패치 파일, Docker 또는 릴리스 입력 구성 | 필수 입력 누락 검사, Windows와 Linux의 포터블용 production 의존성 설치, Docker deps 단계 빌드 |

정확한 경로 필터는 `.github/workflows/storage-change-check.yml`과 `dependency-change-check.yml`에 있다. 동일 브랜치에 새 커밋이 오면 이전 변경 검사를 취소한다. 두 워크플로는 읽기 권한만 사용하며 태그, 릴리스나 이미지를 게시하지 않는다.

## 로컬에서 변경을 완료하기 전

- 저장 경로 수정: `pnpm verify:storage-change`
- 의존성 및 배포 입력 수정: `pnpm check:release-inputs` 및 `pnpm test:release-inputs`

저장 명령은 두 클라이언트 테스트 파일과 다섯 서버 테스트 파일만 실행한다. 실제 서버를 켜는 테스트는 임시 사용자 데이터만 사용한다. 에셋 검사는 시간뿐 아니라 변경 없는 본문 읽기와 폴더 탐색 횟수도 검증한다.

배포 입력 검사기는 릴리스 워크플로의 실제 `app-build` 파일 목록을 읽고, workspace와 lockfile에 선언된 패치가 포터블과 Docker에 포함되는지 확인한다. 현재의 명시적 파일 목록과 COPY 문법을 대상으로 하므로 문법을 바꾸면 검사기도 함께 수정한다. 정적 검사는 모든 Dockerignore 문법을 해석하지 않는다. 실제 Docker deps 빌드가 최종 설치 가능 여부를 검증한다.

CI의 포터블 의존성 검사는 새 임시 폴더에 검증한 입력만 복사하고 릴리스와 같은 `node-linker=hoisted` 및 `--prod --frozen-lockfile`로 설치한다. Docker는 실제 Dockerfile의 deps 단계만 빌드한다. 앱 전체 빌드나 압축 패키지 생성은 추가하지 않는다.

## 릴리스에서 남기는 확인

의존성 설치 전에 빠른 입력 검사를 수행한다. 이후 기존 `verify:release`, 네 플랫폼 패키징과 압축 해제 후 서버 기동 검사를 그대로 실행한다. 이 검사들은 변경 단계 검사를 대체하지 않으며, 전체 검사를 로컬과 CI에서 중복 실행하라는 뜻도 아니다.

변경 검사 성공은 모든 결함이 없다는 보장이 아니다. main push 검사는 커밋 반영 후 실행된다. 브랜치 보호 규칙이나 머지 차단 규칙을 이번 변경에서 추가한 것은 아니다.
