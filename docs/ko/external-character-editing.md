# 외부 편집기로 봇 수정하기

서버가 사용하는 데이터 폴더의 파일을 고치는 방법은 두 가지입니다.

- **앱을 닫고 고치기:** 앱(브라우저 탭)을 모두 닫고 파일을 고친 뒤 다시 열면 반영됩니다. 내용은 JSON 형식과 안전성을 검사한 뒤에 받아들이며, 형식이 깨진 파일은 어느 줄과 칸이 잘못됐는지 알려 줍니다.
- **앱을 연 채로 고치기 (0.9.69부터):** 앱이 열려 있는 동안 캐릭터 파일이나 전역 로어북 파일이 바뀌면, 바뀐 필드와 로어 항목을 보여 주는 확인 창이 뜹니다. `외부 변경 받아들이기`를 누르면 바뀐 캐릭터와 로어북만 외부 내용으로 바꾸고, `앱 내용 유지`를 누르면 외부 파일을 `trash/external-changes-*`에 백업한 뒤 앱 내용으로 덮어씁니다. 고를 때까지 저장을 멈춥니다.
  - `설정 > 공통 설정 > 저장 및 불러오기 > 외부 파일 변경 확인`을 켜면 앱이 화면에 보이는 동안 몇 초마다 확인합니다. 꺼 두면 다음 저장 때 확인 창이 뜹니다.

## 편집할 파일

- `characters/<캐릭터 폴더>/metadata.json`: 캐릭터 설명은 `desc`, 캐릭터 로어북은 `globalLore`입니다. 로어북을 비우려면 `globalLore`를 `[]`로 저장합니다. 캐릭터 ID인 `chaId`는 유지합니다.
- `lorebooks/<ID>.json`: 전역 로어북입니다. 내용을 수정하거나 파일을 제거하면 목록에도 반영됩니다.
- `characters/<캐릭터 폴더>/chats/<채팅 폴더>/metadata.json`: 채팅별 로어북은 `localLore`입니다. 앱을 닫고 고친 뒤 다시 열면 반영됩니다. 채팅 ID인 `id`는 유지합니다. 메시지 본문은 이 파일에 넣지 않습니다.
- `characters/<캐릭터 폴더>/assets/`: 파일을 넣으면 확장자를 제외한 파일명이 추가 에셋 이름으로 등록됩니다. 같은 파일을 교체하면 새 내용으로 바뀌고, 제거하면 이 캐릭터의 해당 이미지 또는 에셋 참조도 제거됩니다. 새 파일은 추가 에셋으로 등록되며 자동으로 대표 이미지나 감정 이미지로 지정되지는 않습니다.

기존 구조에서는 캐릭터 폴더명이 ID이며, V3로 전환한 캐릭터는 표시 이름 기반 폴더를 사용합니다. 앱에서 사용 중인 현재 폴더를 편집하세요. 전환 과정에서 남겨 둔 이전 ID 폴더는 편집 대상이 아닙니다.

새로 생성하거나 새 ID로 임포트한 캐릭터는 처음부터 V3 폴더에 배치합니다. 기존 ID를 갱신하거나 전체 백업을 복원할 때는 기존 구조를 유지합니다. V3에서는 앱에서 바꾼 이미지와 에셋도 저장 시 폴더에 반영합니다. 앱에서 제거한 관리 대상 복사본은 `trash/asset-sync-.../`로 이동하고 KV 원본은 유지합니다. 공유 에셋도 캐릭터별 복사본을 사용하므로 한 폴더에서 수정해도 다른 캐릭터에 전파되지 않습니다.

새로 생성하거나 새 ID로 임포트한 캐릭터는 처음부터 V3 폴더에 배치합니다. 기존 ID를 갱신하거나 전체 백업을 복원할 때는 기존 구조를 유지합니다. V3에서는 앱에서 바꾼 이미지와 에셋도 저장 시 폴더에 반영합니다. 앱에서 제거한 관리 대상 복사본은 `trash/asset-sync-.../`로 이동하고 KV 원본은 유지합니다. 공유 에셋도 캐릭터별 복사본을 사용하므로 한 폴더에서 수정해도 다른 캐릭터에 전파되지 않습니다.

`.sha256`, `.bak`, 임시 파일과 `index/` 파일은 직접 수정하지 않습니다. 에셋은 바로 아래에 있는 일반 파일을 대상으로 하며, 숨김 파일과 편집기 임시 파일, 심볼릭 링크는 가져오지 않습니다. 파일 하나의 크기 제한은 64MiB입니다.

## 동시에 앱을 사용할 때

열린 채팅과 작성 중인 메시지는 유지됩니다. 확인 창에서 외부 변경을 받아들이면 이 창에서 아직 저장하지 않은 다른 편집은 그대로 남고, 같은 항목을 고친 내용은 브라우저의 `risubard-live-file-conflicts` 복구 기록에 보관합니다. 브라우저에 기록할 수 없으면 JSON 파일로 내려받습니다.

JSON 문법이 잘못된 파일은 확인 창에 위치와 함께 표시되며 받아들일 수 없습니다. 파일을 고치면 확인 창이 새 내용으로 다시 뜨고, `앱 내용 유지`를 고르면 잘못된 파일을 백업한 뒤 앱 내용으로 되돌립니다. 이미 실행 중인 모델 요청의 입력은 바꾸지 않으며, 받아들인 내용은 다음 요청에 사용됩니다.

확인 창은 캐릭터 메타데이터와 전역 로어북을 비교합니다. 채팅 메타데이터, 설정 파일, 캐릭터 에셋은 앱을 닫고 고칩니다. 메시지 본문 JSONL이나 설정 파일의 임의 편집, 캐릭터 폴더 삭제 및 ID 변경을 자동 병합하는 기능은 아닙니다. 공유 에셋의 기존 원본은 유지하므로 한 캐릭터에서 교체하거나 제거해도 다른 캐릭터가 사용하는 원본을 삭제하지 않습니다.
