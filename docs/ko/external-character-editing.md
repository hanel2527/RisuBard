# 외부 편집기로 봇 수정하기

서버가 사용하는 데이터 폴더의 파일을 저장하면 열린 앱에 자동 반영됩니다. 별도의 편집 모드나 페이지 새로고침은 필요하지 않습니다. 화면이 열려 있을 때 약 0.75초 간격으로 확인하며, 새 메시지를 보내기 전에도 확인합니다. 연속 저장 중에는 파일이 잠시 안정될 때까지 기다립니다.

## 편집할 파일

- `characters/<캐릭터 폴더>/metadata.json`: 캐릭터 설명은 `desc`, 캐릭터 로어북은 `globalLore`입니다. 로어북을 비우려면 `globalLore`를 `[]`로 저장합니다. 캐릭터 ID인 `chaId`는 유지합니다.
- `lorebooks/<ID>.json`: 전역 로어북입니다. 내용을 수정하거나 파일을 제거하면 목록에도 반영됩니다.
- `characters/<캐릭터 폴더>/chats/<채팅 폴더>/metadata.json`: 채팅별 로어북은 `localLore`입니다. 항목을 지우거나 `[]`로 비우거나 필드를 제거하면 열린 채팅에도 반영됩니다. 채팅 이름 등 메타데이터도 반영되며 채팅 ID인 `id`는 유지합니다. 메시지 본문은 이 파일에 넣지 않습니다.
- `characters/<캐릭터 폴더>/assets/`: 파일을 넣으면 확장자를 제외한 파일명이 추가 에셋 이름으로 등록됩니다. 같은 파일을 교체하면 새 내용으로 바뀌고, 제거하면 이 캐릭터의 해당 이미지 또는 에셋 참조도 제거됩니다. 새 파일은 추가 에셋으로 등록되며 자동으로 대표 이미지나 감정 이미지로 지정되지는 않습니다.

기존 구조에서는 캐릭터 폴더명이 ID이며, V3로 전환한 캐릭터는 표시 이름 기반 폴더를 사용합니다. 앱에서 사용 중인 현재 폴더를 편집하세요. 전환 과정에서 남겨 둔 이전 ID 폴더는 편집 대상이 아닙니다.

새로 생성하거나 새 ID로 임포트한 캐릭터는 처음부터 V3 폴더에 배치합니다. 기존 ID를 갱신하거나 전체 백업을 복원할 때는 기존 구조를 유지합니다. V3에서는 앱에서 바꾼 이미지와 에셋도 저장 시 폴더에 반영합니다. 앱에서 제거한 관리 대상 복사본은 `trash/asset-sync-.../`로 이동하고 KV 원본은 유지합니다. 공유 에셋도 캐릭터별 복사본을 사용하므로 한 폴더에서 수정해도 다른 캐릭터에 전파되지 않습니다.

`.sha256`, `.bak`, 임시 파일과 `index/` 파일은 직접 수정하지 않습니다. 에셋은 바로 아래에 있는 일반 파일을 대상으로 하며, 숨김 파일과 편집기 임시 파일, 심볼릭 링크는 가져오지 않습니다. 파일 하나의 크기 제한은 64MiB입니다.

## 동시에 앱을 사용할 때

열린 채팅과 작성 중인 메시지는 유지됩니다. 앱과 파일에서 서로 다른 항목을 바꾸면 양쪽 변경을 보존합니다. 같은 항목을 동시에 바꾸면 외부 파일을 적용하고, 겹친 앱 값은 알림과 함께 브라우저의 `risubard-live-file-conflicts` 복구 기록에 보관합니다. 브라우저에 기록할 수 없으면 JSON 파일로 내려받습니다.

서버가 이미 수신했지만 파일에 반영하기 전인 앱 편집도 보호합니다. 이 경우 서버 데이터 폴더의 `trash/live-files-recovery/<ID>.json`에 앱 수정본과 충돌 정보를 보존하고 경로를 알립니다. 이 기록은 전체 백업에 포함됩니다. 반영 도중 실패하면 다음 확인에서 재시도하며, 서버가 재시작되어도 미완료 기록을 읽어 이어서 반영합니다. 완료한 복구 파일은 자동 삭제하지 않습니다.

JSON 문법이나 필드 형식이 잘못되면 마지막 정상 화면을 유지하고 저장과 새 전송을 잠시 보류합니다. 파일을 고쳐 저장하면 자동으로 다시 시도합니다. 이미 실행 중인 모델 요청의 입력은 바꾸지 않으며, 수정 내용은 다음 요청에 사용됩니다.

외부 편집은 캐릭터와 채팅 메타데이터, 전역 로어북과 캐릭터 에셋을 대상으로 합니다. 메시지 본문 JSONL이나 설정 파일의 임의 편집, 캐릭터 폴더 삭제 및 ID 변경을 자동 병합하는 기능은 아닙니다. 공유 에셋의 기존 원본은 유지하므로 한 캐릭터에서 교체하거나 제거해도 다른 캐릭터가 사용하는 원본을 삭제하지 않습니다.
