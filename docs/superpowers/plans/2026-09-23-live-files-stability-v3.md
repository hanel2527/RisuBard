# 실시간 편집 안정성과 신규 V3 배치

사용자 승인: 재현된 세 충돌 수정과 V3 변경 적용.

- [x] ACK 이후 같은 필드 충돌에서 서버 복구본을 먼저 보존한다.
- [x] canonical 게시와 캐시 적용 사이 실패 시 재시도하며 미완료 복구 기록을 재시작 후 읽는다.
- [x] 나중에 게시된 replica 소유권을 live 인덱스와 합친다.
- [x] 신규 ID를 V3 package와 mapping 단일 journal로 게시한다. 기존 ID, 초기 이관, 전체 백업 복원은 구조를 유지한다.
- [x] 앱 에셋 변경을 V3 폴더와 소유권 인덱스에 동기화한다. 제거한 복사본과 공유 KV를 보존한다.
- [x] 격리 테스트에서 게시 전후 실패, journal 복구, 폴더와 앱 간 교체, 공유 에셋 격리 및 HTTP 동기화를 확인한다.

복구 기록은 전체 백업 대상인 `trash/live-files-recovery/`에 저장한다. 사용자 데이터에서 재현 테스트를 하지 않는다.
