# 바드위키 초장기 챗 전체 구현 실행 기록

Spec: `docs/architecture/2026-09-29-bardwiki-long-chat-checkpoint.md`

사용자가 첫 수정에서 멈추지 말고 나머지 설계도 구현하라고 확인했다. 이 계획은 앞선 '첫 구현' 계획의 범위 제한을 대체한다. 공개판 현재 브랜치를 사용하며 기존의 다른 작업은 보존한다.

## 병렬 작업과 인터페이스

- [x] 자동 확장: `dynamicMemoryBudget.ts`의 `resolveDynamicMemoryBudget(settings, turnCount)`가 target/events/perSource/maximum/sourceLimit/candidateLimit/directSeedLimit를 반환한다. off/economy/balanced/recall 한 드롭다운과 최대 허용값만 노출하고 기본값을 덮어쓰지 않는다. 실제 요청과 표시가 같은 계산기를 쓴다.
- [x] 부분 편집: 긴 단일 대상 문서를 원문 위치와 hash가 있는 작은 구간으로 나누고 모든 배치를 검증한 뒤 한 번 저장한다. 누락/중복/알 수 없는 구간, 잘림과 충돌 시 원문을 보존한다. 입력하지 않은 내용을 전체 교체하지 않는다.
- [x] 캐릭터 연대기: 현재 사건과 명확한 인물 링크에서 읽기 전용 연대기를 생성한다. 인물 선택, 페이지 이동, 사건 및 원문 탐색을 연결하고 정본 사본이나 모델 호출을 추가하지 않는다.
- [x] 검색: `retrievalLimits: {candidates,directSeeds}`를 클라이언트, HTTP 검증, 서버 서비스와 inquiry에 연결한다. 기본 64/32, 동적 안전 최대 256/128. 최종 토큰과 문서 수는 별도로 제한한다.
- [x] 복수 구간: 같은 문서의 독립적인 의미 적중 구간을 최대 3개 유지한다. 겹치는 구간은 합치고 실제 자료별 토큰 예산 안에 넣는다. 재순위화 후에도 검증된 원문 위치를 유지한다.
- [x] 원문 의미 검색: 기존의 선택형 임베딩을 켠 경우에만 활성 원문 구간을 백그라운드에서 색인한다. 수정/삭제/OOC/비활성/챗 변경을 반영한다. 조회 시 원문과 위치를 다시 확인하고 기존 원문 회수 예산을 공유한다. 동일 질의 벡터를 위키 검색과 재사용한다.
- [x] 평가: 후보 적중과 최종 근거 적중을 구분하는 실제 inquiry 회귀/규모 평가를 실행한다. 인공 자료의 연결 검증을 실제 모델 80%/96% 달성으로 표시하지 않는다.
- [x] 통합: 관련 회귀 테스트, 형 검사, 실제 화면의 데스크톱/모바일 조작 및 저장 유지 확인, 독립 리뷰, 최신 패치노트와 구현 상태 갱신.

## 결정 기록

- 숫자 계수는 초기 조정값이다. 100턴 이후 두 배 성장에 따른 완만한 증가를 적용하며 사용자가 최대치를 조절할 수 있다.
- 분석 설정은 현재 출력 한도와 연결되어 있으므로 이번 자동 확장 대상은 검색 예산으로 한정한다. 최근 턴 수, 출력 길이, 재시도와 대기 시간을 자동 증가시키지 않는다.
- 원문 색인은 파생 캐시이며 외부 임베딩 사용 여부는 기존 사용자의 선택을 따른다. 자동 확장 선택만으로 외부 전송을 켜지 않는다.
- 새로운 공개 릴리스나 비공개판 동기화는 이번 요청 범위가 아니다.
