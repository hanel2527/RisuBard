# RisuBard v0.9.13

이번 버전은 대규모 로어북을 고정된 문맥 예산 안에서 검색하는 `Bard Lore`를 추가했습니다. 메타데이터 분석의 비용 확인·중단·재개·실패 진단을 강화하고, 로어북 작업 공간, 캐릭터 사이드바와 저장소, 페르소나 바인딩 및 플러그인 구조화 출력 흐름도 함께 정리했습니다.

## [기능] Bard Lore 제한 검색

- **안전한 업그레이드:** 기존 캐릭터 로어북을 변경하지 않고 별도의 Bard Lore 사본을 만들 수 있습니다. 편집 화면의 레거시/Bard 전환과 실제 생성에 Bard Lore를 사용할지는 각각 독립적으로 선택합니다.
- **결정론적 검색:** 생성할 때 AI를 추가 호출하지 않고 `항상 필수`, 키·별칭 직접 적중, 한·영 sparse 관련도와 명시된 보조 링크를 조합해 장면에 필요한 항목만 선택합니다. 유형이나 태그가 같다는 이유만으로 관련 없는 항목을 확장하지 않습니다.
- **구조화 질의 라우터:** 작품·성별·역할·소속처럼 사용자가 승인한 패싯과 캐릭터·장소 같은 종류 어휘, 요청 개수와 장면/목록/설명 의도를 로컬에서 해석합니다. 예를 들어 `페르소나 3의 남자 캐릭터 아무나 3명`은 direct·패싯·관계 후보가 섞여도 명부 전체 없이 최종 원자 항목 3개를 선택합니다.
- **코퍼스 범위와 값 정규화:** 캐릭터 이름처럼 전체 로어북을 가리키는 말은 개별 항목의 작품 조건으로 오인하지 않습니다. 저장된 `gender=남성/여성`도 설정 어휘를 통해 `남자/여자`, `male/female` 질의와 정규화해 기존 승인 메타데이터를 다시 만들지 않고 사용할 수 있습니다.
- **모호한 별칭 차단:** `페르소나`처럼 서로 다른 여러 패싯 값이 공유하는 일반 별칭은 조건으로 채택하지 않으며, 더 긴 코퍼스명이나 고유 조건 안에 포함된 짧은 엔티티 별칭도 별도 검색 시드로 중복 해석하지 않습니다.
- **종류·속성·개수 최종 보장:** `남자 캐릭터 3명`처럼 종류·속성·개수를 명시한 요청은 필수 시스템 로어를 유지하면서 모든 직접·링크·그래프·sparse 후보에 같은 조건을 적용해 원자 항목 3개만 최종 주입합니다. 검색 전용 명부는 결과 수를 차지하지 않으며, 장면의 장소 앵커는 제목으로만 적중해도 장소 본문과 주변 관계 검색을 함께 제공합니다.
- **묘사형 인물 검색:** 패싯 값과 별칭도 가중 sparse 검색 필드로 사용합니다. 성별·작품처럼 설정된 필터 패싯은 후보를 제한하고, 외모·성격·역할·능력 같은 설명 패싯은 여러 묘사가 한 문장에 섞여도 전역 AND 조건으로 묶지 않고 각 인물의 관련도 근거로 사용합니다.
- **정·역방향 관계 검색:** `supporting`, `discoverable`, `ambient`, `none` 관계 정책을 구분합니다. 장소에서 재학·근무 인물을 찾는 것처럼 승인된 역방향 링크를 설정된 깊이까지만 탐색하며, 깊이 0에서는 확장을 완전히 끕니다. 같은 유형이나 패싯만 공유하는 항목은 연결하지 않습니다.
- **검색 전용 인덱스 항목:** 복합 명부와 디렉터리는 `검색 인덱스로만 사용`으로 지정할 수 있습니다. 해당 본문은 모델에 주입되거나 토큰 예산을 소비하지 않지만 별칭·패싯·명시 링크는 라우팅 시드로 사용할 수 있습니다.
- **분리된 문맥 예산:** `항상 필수` 시스템 계약은 일반 검색의 목표 토큰과 최대 항목 수를 잠식하지 않습니다. 다만 필수와 검색 결과를 합친 전체가 캐릭터별 절대 최대 토큰을 넘으면 내용을 몰래 자르지 않고 원인을 표시합니다.
- **소프트 설정:** 검색 점수 기준, 직접 적중·링크 점수와 감쇠, 최소 검색어 길이, 한중일 부분 일치, 이름·키·별칭·태그·패싯·요약·본문별 가중치, 필터 패싯 키와 패싯 값 질의 어휘를 저장할 수 있습니다. 숫자 입력에는 앱이 임의의 숨은 최대값을 적용하지 않습니다.
- **검색 미리보기:** 임의의 장면이나 요청을 입력해 해석된 의도, 대상 종류·개수, 패싯 조건, 엔티티 앵커, 관계 경로, 필수/검색 예산과 선택·제외 사유를 생성 전에 확인할 수 있습니다.
- **생성 파이프라인 연동:** Bard Lore가 활성화되면 검색으로 선택된 캐릭터 로어만 기존 채팅·모듈 로어와 독립적으로 주입합니다. 선택된 Bard Lore 본문은 다시 로어 검색을 발동하지 않아 재귀적인 대량 주입을 막습니다.

## [기능] Bard Lore 메타데이터 관리

- **항목별 메타데이터:** 각 항목의 활성화 정책, 로어 유형, 별칭, 태그, 검색 요약, 구조화 패싯, 프롬프트 역할과 명시 관계 링크를 직접 편집할 수 있습니다.
- **Bard 전용 일괄 편집:** 여러 항목을 선택하면 레거시의 `항상 활성`, 멀티플 키와 정규식 설정 대신 Bard 활성화와 로어 유형을 일괄 지정하고, 별칭·태그를 기존 값을 보존하면서 추가하거나 제거할 수 있습니다.
- **링크 무결성:** 자기 자신을 대상으로 하는 링크를 만들 수 없으며, 대상 항목을 삭제하면 남은 항목의 끊어진 링크도 함께 정리합니다.
- **명시적 생성 스위치:** `Bard Lore 활성화` 스위치로 레거시 로어북과 Bard Lore 중 생성에 사용할 방식을 분명하게 선택할 수 있습니다. 두 검색 방식을 동시에 실행해 비용을 이중으로 쓰지 않습니다.

## [기능] AI 메타데이터 분석

- **분석 실행 위치:** Bard Lore 탭과 편집기에서 현재 항목, 현재 및 연결 항목, 캐릭터 항목만, 전체 Bard Lore 중 범위를 선택해 분석할 수 있습니다. 인물 검색 어휘만 보강할 때 전체 로어북을 다시 분석할 필요가 없습니다.
- **인물 검색 계약 강화:** 캐릭터 분석은 근거가 있는 작품·성별 패싯을 일관된 키로 만들고, 외모·학년·사회적 역할·성격·기술·약점·취향·반복 행동의 자연어 검색어를 한국어와 영어로 제안합니다. 서로 다른 값에 `페르소나` 같은 범주명 하나를 공통 별칭으로 붙이지 않도록 지시합니다.
- **복합 명부 원자화:** AI가 복합 명부·디렉터리를 감지하면 원본에 실제 존재하는 연속 인용만으로 파생 원자 항목 초안을 제안합니다. 승인 전에는 아무것도 바꾸지 않으며, 승인해도 레거시 원본은 유지합니다. 이미 같은 원자 항목이 있으면 본문을 보존하고 메타데이터만 병합하며, 새 파생 항목은 안정 ID로 생성되어 재승인해도 중복되지 않습니다.
- **구조화 메타데이터 분석:** 분석 초안은 패싯과 네 가지 관계 검색 정책, 검색 전용 인덱스 여부를 포함합니다. 파생 원자 항목의 이름·원문 인용·유형·패싯도 승인 전에 펼쳐 볼 수 있습니다.
- **요청 전 비용 확인:** 모델에 보내기 전에 모든 분석 대상의 이름과 원문을 펼쳐 보고, 실제 배치 프롬프트 기준 대상 수, 요청 횟수, 예상 입력 토큰과 최대 출력 토큰을 확인할 수 있습니다.
- **분석 제한 설정:** 배치당 항목 수, 입력·출력 토큰 제한, 연결 깊이와 temperature를 분석 창에서 캐릭터별로 변경할 수 있습니다. 숫자 입력에는 하드코딩된 앱 최대값을 두지 않습니다.
- **안전한 초안 승인:** 결과는 로어 본문을 바꾸지 않는 승인 대기 초안으로 저장합니다. 기존 수동 메타데이터는 기본적으로 유지하고 `기존 수동 메타데이터 교체`를 명시적으로 선택했을 때만 덮어씁니다. 기존 atom 대상이 승인 전에 변경되거나 삭제되면 복합 원본을 검색 전용으로 바꾸지 않고 해당 초안을 검토 상태로 보존합니다.
- **중단·재개·부분 승인:** 창을 닫거나 분석을 중단해도 완료된 배치와 실패·대기 상태를 캐릭터에 보존합니다. 성공한 초안을 먼저 승인한 뒤에도 남은 배치를 이어서 분석하거나 실패한 배치만 새 제한값으로 다시 계산해 재시도할 수 있습니다.
- **진행 내역과 실패 진단:** 완료 배치, 생성된 초안, 실패 배치와 각 배치의 대상 항목을 표시합니다. JSON 파싱, entries 누락, 잘못된 항목·링크 형식, 대상 누락과 원본 변경을 구분해 실패 원인을 보여 줍니다.

## [호환성] 캐릭터 카드와 데이터 보존

- **CHARX 왕복 보존:** Bard Lore 항목, 검색·분석 설정과 승인 대기 초안을 CHARX V2·V3의 RisuBard 전용 확장 영역에 저장합니다.
- **레거시 호환 유지:** 가져오기와 다시 내보내기 과정에서도 표준 로어북은 변경하지 않고 Bard Lore 상태를 독립적으로 왕복합니다.
- **메타데이터 전용 공유:** Bard Lore 탭과 편집기에서 검색 메타데이터 오버레이만 JSON으로 내보내고 다른 사본의 같은 로어북에 가져올 수 있습니다. 일반 레거시 본문은 파일에 포함하지 않으며, 원본 지문으로 항목을 대조하고 링크 ID를 새 캐릭터에 맞게 다시 연결합니다.
- **검증된 파생 항목 복원:** 분석으로 만든 원자 항목은 복원에 필요한 원문 인용만 포함합니다. 가져올 때 해당 인용이 현재 복합 원본에 실제로 존재하는 경우에만 파생 항목을 만들며, 잘못된 파일은 일부만 적용하지 않고 전체를 거부합니다.
- **Bard 메타데이터 정화:** 캐릭터의 Bard 메타데이터, 설정, 분석 초안과 파생 사본만 한 번에 제거할 수 있습니다. 기존 레거시 로어북은 그대로 유지됩니다.
- **로드 경계 복구:** 손상되거나 이전 형식으로 저장된 Bard Lore 설정을 정규화하고, 실행 중 종료된 분석 배치는 재개 가능한 상태로 복원합니다.

## [UI] 로어북 작업 공간

- **명확한 화면 구분:** 캐릭터·채팅·설정 탭과 레거시 로어북/Bard Lore 탭을 구분하고, 생성 적용 여부를 별도 스위치로 표시했습니다.
- **사이드바 레이아웃:** 제목, 탭, 설정 카드와 입력 행을 채팅 사이드바와 같은 간결한 계층으로 정리해 좁은 너비에서도 라벨과 입력값이 겹치지 않게 했습니다.
- **Bard 편집기 배치:** 본문, 메타데이터, 링크와 AI 분석 도구를 한 작업 공간에서 관리하며, 좁은 화면에서도 검사기와 도구 모음이 겹치거나 화면 밖으로 넘치지 않도록 조정했습니다.
- **요청 상태 가시성:** 분석 중인 요청 상태 카드가 일반 대화상자 뒤에 가려지지 않게 했습니다. 확인창과 로딩 차단창은 계속 요청 상태 카드보다 위에 표시됩니다.

## [UI] 캐릭터 저장소

- **크기 조절 창:** 다른 관리 창과 같은 리사이즈 핸들을 추가하고, 창의 실제 너비에 맞춰 내부 레이아웃이 반응하도록 변경했습니다.
- **모바일 폴더 사이드바:** 좁은 화면에서는 왼쪽 파일 트리를 버튼으로 여닫는 오프캔버스 사이드바로 전환합니다. 배경이나 폴더를 선택하면 닫히고 키보드 포커스도 열기·닫기 버튼으로 돌아옵니다.
- **안정적인 카드 그리드:** 카드 열과 행을 가용 너비에 맞춰 계산해 캐릭터 카드가 서로 겹치지 않도록 했습니다.
- **선택 도구 모음:** 이동·복제·삭제 도구를 카드 위의 절대 위치에서 일반 레이아웃으로 옮겼습니다. 버튼은 가용 너비에 맞춰 줄바꿈되고 모바일에서는 2열로 배치됩니다.
- **모바일 조작성:** 검색·정렬과 주요 버튼의 터치 영역을 키웠으며, 동작 줄이기 설정에서는 사이드바 전환 애니메이션을 사용하지 않습니다.

## [UI] 캐릭터 사이드바

- **크기 조절 캐릭터 목록:** 캐릭터 사이드바 오른쪽을 드래그해 고정 캐릭터 목록을 최대 3열로 넓힐 수 있습니다. 메뉴·페르소나 버튼은 2열부터 캐릭터 카드와 같은 간격으로 나란히 배치되고, 저장소를 포함한 나머지 항목은 중앙 정렬되며, 목록이 길어지면 오른쪽 스크롤바로 탐색할 수 있습니다.

## [편의성] 페르소나 바인딩

- **연속 선택:** 채팅 사이드바에서 다른 페르소나를 바인딩해도 선택 창이 즉시 닫히지 않아 여러 후보를 확인할 수 있습니다.
- **현재 바인딩에서 시작:** 현재 바인딩이 캐릭터 페르소나라면 선택 창을 캐릭터 탭과 해당 항목에서 바로 엽니다.
- **전역 선택 보호:** 바인딩 대상을 고르는 동안에는 전역 기본 페르소나를 바꾸지 않고 선택 창 내부의 현재 선택만 갱신합니다.

## [호환성] 플러그인 구조화 출력

- **선택적 네이티브 스키마:** 플러그인 API v2·v3 제공자가 `structuredOutput`을 선언하면 JSON Schema를 네이티브 `response_schema`로 받을 수 있습니다. 선언하지 않은 기존 플러그인은 이전 프롬프트 방식으로 계속 동작합니다.
- **안전한 호환 재시도:** 공급자가 네이티브 스키마 필드를 거부한 경우에만 해당 필드를 제거해 한 번 재시도하며, JSON 전용 프롬프트 제약은 유지합니다.
- **요청 상태 위임:** 자체 생성 정보 창을 사용하는 플러그인은 제공자 옵션으로 RisuBard 요청 상태 창을 대신할 수 있어 두 상태 창이 중복되지 않습니다.

## [안정성] 플러그인 분석 응답

- **분석 temperature 우선:** Bard Lore 분석에서 지정한 temperature가 플러그인 경로에서도 전역 모델 설정보다 우선 적용됩니다.
- **설명 혼합 응답 처리:** 플러그인이 유효한 단일 결과 JSON 앞뒤에 reasoning이나 설명을 붙여도 완전한 `entries` 객체를 찾아 기존 스키마 검증에 전달합니다.
- **손상 응답 보존 원칙:** 잘리거나 손상된 JSON은 임의로 고치거나 숨겨진 유료 재요청을 하지 않고 실패 배치로 남깁니다. 이미 완료된 초안은 그대로 보존됩니다.
