# RisuBard v0.9.40

## [기억] 위키 프리셋과 캐릭터 정본 정리

- **이전 공식 프리셋 보관:** 기존 작성 지침을 `공식기본-260922`로 함께 제공해 필요할 때 선택할 수 있습니다. 새 공식 기본값은 현재 상태, 관계와 신뢰, 지식과 비밀, 주요 전환의 역할을 구분하고 같은 정보의 반복을 줄입니다.
- **선택형 장비와 분량 압축:** 장비와 소지품 블록은 기본으로 켜지고, 분량 압축 블록은 기본으로 꺼집니다. 공식 프리셋에서도 두 블록을 켜거나 끌 수 있으며 압축은 필요한 사실을 보존하면서 중복 설명과 연속된 행적을 정리하도록 유도합니다.
- **긴 정본 갱신:** 위키 본문과 정본 절 수정안이 12,000자를 넘었다는 이유로 저장과 갱신을 거부하던 제한을 제거했습니다. 대화에 보내는 기억의 검색 및 토큰 예산은 유지됩니다.
- **프리셋 선택 개선:** 채팅 프리셋 설정처럼 검색 가능한 선택 창을 사용해 목록이 잘리는 문제를 해결했습니다.

## [성능] 시작과 저장 대기 감소

- **필요한 대화부터 불러오기:** 검증된 파일 저장소에서는 시작할 때 전체 세이브와 모든 대화를 다시 조립하지 않고 설정, 대화 목록과 현재 대화부터 읽습니다. 기존 백업과 구형 저장 데이터의 복구 경로는 유지합니다.
- **캐릭터 에셋 읽기 단축:** 캐릭터별 에셋 시험 전환을 사용하면 평소 이미지 읽기에서 반복하던 파일 정보 조회와 전체 해시 계산을 생략합니다. 복사와 명시적 재검증 때만 원본을 비교하며, 복사본에 문제가 있으면 기존 KV 원본을 읽습니다.

## [성능] 플러그인 위키 반복 조회 감소

- **BardWiki 컨텍스트 재사용:** 플러그인이 같은 대화를 반복 조회할 때 위키 컨텍스트 요청과 결과를 최대 30초 동안 공유합니다. 대화나 설정이 바뀌거나 앱에서 위키를 수정하면 캐시를 비웁니다.

## [기억] 선택형 바드위키 임베딩 검색

- **의미로 기억 찾기:** 공통 설정에서 바드위키 임베딩을 켤 수 있습니다. Hypa와 같은 모델, URL과 API 키를 사용하며 기본값은 꺼짐입니다. 사용하지 않아도 기존 바드위키 검색은 그대로 작동합니다.
- **대화 맥락과 세부 근거 회수:** 현재 입력과 최근 대화를 함께 활용하고 긴 위키 문서를 문단 단위로 검색해, 표현이 다른 과거 사건과 작은 단서를 찾습니다. 검색된 사건은 해당 원문 구간으로 연결하며 기존 기억 토큰 상한을 유지합니다.
- **백그라운드 준비와 캐시:** 문서 벡터를 백그라운드에서 준비하고 재사용합니다. 모델 변경, 문서 수정과 삭제를 반영하며, 준비 중이거나 임베딩 요청이 실패하면 기존 검색으로 계속 진행합니다.
- **중복 요청과 취소 정리:** 화면 갱신 때문에 같은 임베딩을 반복 요청하지 않으며, 클라이언트가 취소한 프록시 요청은 서버에서도 중단합니다. 실제 외부 서버 오류는 계속 기록합니다.

## [편의성] 공통 설정 빠른 이동

- **한 열 목차:** 공통 설정 왼쪽의 세로 목차에서 각 섹션과 의미 검색 임베딩으로 바로 이동할 수 있습니다. 항목은 간결한 행으로 표시하고 긴 설명은 제목 옆 도움말에서 확인합니다.
- **임베딩 모델 설정 연결:** 바드위키 의미 검색의 모델 설정 버튼을 누르면 Hypa 임베딩 모델 설정으로 바로 이동합니다.

## [편의성] 중복 이름 자동 정리

- **캐릭터 삭제와 용량 자동 회수:** 개별 삭제와 보관소 일괄 삭제는 두 번 확인한 뒤 3일 대기 없이 삭제합니다. 저장이 완료되면 해당 캐릭터와 채팅 폴더, V3 전환 때 남긴 이전 ID 폴더도 제거합니다. 삭제한 캐릭터의 KV 에셋 중 다른 캐릭터, 채팅, 설정과 플러그인에서 사용하지 않는 파일은 자동으로 회수합니다. 공유 파일은 유지하며, 참조 정보를 확인할 수 없으면 에셋 정리를 중단합니다.



- **캐릭터와 채팅 이름 충돌 방지:** 가져오기, 복제, 직접 이름 변경과 새 대화 생성에서 같은 표시 이름이 있으면 `(2)`, `(3)`처럼 번호를 붙입니다. 기존 데이터와 안정 ID는 바꾸지 않습니다.

## [안정성] 큰 채팅 분할 저장

- **선택적 청크 업로드:** 공통 설정의 저장 및 불러오기에서 큰 채팅을 나눠 전송할 수 있습니다. 서버나 프록시의 요청 크기 제한에 대응하며 기본값은 꺼짐입니다. 청크 크기는 기본 8MiB이고 1MiB부터 64MiB까지 조절할 수 있습니다.

## [안정성] 점진적 저장 구조 전환 기반

- **한 캐릭터씩 시험 전환:** 개발자 항목에서 선택한 캐릭터 하나의 본문, 채팅과 전용 에셋을 V3 이름 기반 폴더로 전환할 수 있습니다. 나머지 캐릭터는 기존 구조를 그대로 사용합니다.
- **이름 기반 폴더 유지:** 캐릭터와 채팅의 안정 ID는 유지하면서 읽기 쉬운 폴더 이름을 사용합니다. 이름이 바뀌면 다음 저장에서 폴더 이름도 안전하게 갱신하고, 충돌에는 번호를 붙입니다.
- **최신 상태 그대로 복귀:** 기존 구조로 되돌릴 때 V3 전환 뒤 생긴 채팅과 편집 내용까지 ID 폴더로 옮긴 뒤 경로 정보를 해제합니다. 중간 종료가 발생해도 다음 시작에서 journal을 재생할 수 있습니다.
- **기존 형식 유지:** 기존 KV 원본과 백업 형식은 유지합니다. 자동 일괄 전환은 하지 않으며 캐릭터별 명시적 선택이 필요합니다.

## [안정성] 백업 복원 중단 대응

- **복구 가능한 게시:** 파일 정본이 포함된 백업은 KV 색인, 캐릭터 파일과 인레이를 하나의 복구 기록으로 교체합니다. 복원 도중 종료되면 다음 시작에서 남은 게시를 마치며 기존 자료는 휴지통 아래에 보존합니다.
- **중복 백업 방지:** 이름 기반 경로를 시험한 캐릭터는 현재 폴더만 백업하고 보존된 이전 폴더를 중복 수집하지 않습니다. 목록 수집 중 경로가 바뀌거나 파일 접근이 실패하면 불완전한 목록을 사용하지 않습니다.

## [안정성] 바드위키 인물 연속성

- **지속 정보 보존:** 최신 장면을 갱신할 때 관계와 신뢰, 정신 상태, 지식, 약속, 부상과 중요한 장비 정보를 유지하도록 캐릭터 작성 지침을 개선했습니다.
- **간결체 보강:** 간결하게 쓰면서 서로 다른 사실을 빠뜨리지 않도록 하고, 필요한 경우 지속적인 인물 정보와 현재 상황을 나눠 정리합니다.
- **기존 프리셋 반영:** 기본 위키 프리셋과 기존 사용자 프리셋에 같은 지침을 적용하며 사용자 작성 블록은 유지합니다.

## [안정성] 그리모어 대형 명단 분석

- **출력량에 맞춘 분할:** 연표와 명단 분석에서 인물별 예상 출력량을 고려해 배치를 나누고 권장 출력 한도를 계산합니다.
- **남은 항목만 재시도:** 잘린 응답에서 복구한 완료 항목은 보존하고 실패한 항목만 더 작은 배치로 이어서 분석합니다. 단일 항목을 무한 재시도하지 않습니다.
- **실패 원인 진단:** 플러그인이 제공한 종료 사유와 토큰 사용량을 이용해 출력 한도 초과 원인을 확인합니다. 해당 정보를 반환하는 플러그인 버전이 필요합니다.

## [호환성] 아카라이브 챗 저장 서식

- **생각과 대사 색상:** `아카라이브 챗 저장기`로 복사할 때 글자색을 유지하고 게시 시 노란 형광펜 배경이 생기지 않도록 수정했습니다.
- **이미지 프레임 제거:** 이미지 영역의 흰 테두리와 여백을 제거하고 가운데 정렬과 둥근 모서리는 유지합니다. 이미지만 감싼 표와 중첩 영역도 함께 정리합니다.

## [UI] 시작 화면 진행 상태

- **첫 화면 브랜딩:** 앱 코드와 화면 스타일을 불러오기 전에 RisuBard 배너를 표시합니다. 외부 폰트 로딩이 첫 화면을 가리지 않습니다.
- **실제 시작 단계 표시:** 저장소 초기화, 저장 데이터 읽기와 해석, 플러그인 로드 등 현재 작업을 표시합니다. 시작에 실패하면 해당 단계와 오류를 화면에 남깁니다.
