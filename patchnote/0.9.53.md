# RisuBard v0.9.53

동적 분석 토큰의 모델 출력 한도 초과와 과거 턴 재분석 후 사건 순서가 뒤섞이는 문제를 수정했습니다. 중복되는 인물 연대기 탭을 제거하고 위키 기본 지시문의 현재 상태 갱신을 보완했습니다.

## [안정성] 동적 분석 토큰과 모델 출력 상한

- **출력 상한 적용:** 장기기억 동적 한도가 늘어나도 모델 프리셋에 등록된 출력 상한 이내로 요청합니다. 상한 정보가 없는 이전 프리셋은 실제 모델과 일치하는 기본 제공 정보로 보완해 Vertex Gemini의 과도한 출력 토큰 요청 오류를 방지하며, 저장된 기본값은 유지합니다.
- **기본값과 동적값 구분:** 숫자 입력칸은 편집 전후 모두 기본값을 표시하고 동적 계산값은 아래에 따로 표시합니다. 분석값에는 모델 출력 상한에 따라 줄어들 수 있음을 안내해, 값을 낮췄는데 다시 커지거나 고정된 것처럼 보이던 혼란을 줄였습니다.

## [안정성] 재분석한 사건의 대화 순서 유지

- **원본 턴 기준 정렬:** 누락된 과거 사건을 나중에 생성하거나 재분석해도 이야기 목록과 사건 폴더는 원본 대화 순서를 따릅니다. 원본 위치는 메시지 ID로 확인하며, 위치를 확인할 수 없는 사건은 뒤에 표시합니다.
- **분석 순서 일치:** 다음 사건의 직전 사건 선택과 새 아크플롯 묶음에도 같은 순서를 적용합니다. 위키를 계승한 새 챗에서는 이전 아크플롯의 체크포인트를 이어갑니다. 이미 작성된 아크플롯 본문을 소급해서 다시 쓰지는 않습니다.
- **기존 사건 정보 유지:** 같은 출처의 사건을 재분석할 때 원래 생성 시각을 유지하고 수정 시각만 갱신합니다.

## [UI] 인물 연대기 탭 제거

- **인물 연대기 제거:** 기존 사건을 인물별로 모아 보여주던 탭을 제거했습니다. 인물 문서, 사건 문서, 작중 행적과 원본 채팅은 그대로 유지됩니다.

## [편의성] 위키 기본 지시문의 현재 상태 갱신

- **종료된 지시 정리:** 완료나 만료가 확인된 과제와 임시 지시를 인물 문서에서 정리하도록 기본 지시문을 수정했습니다. 아직 받지 못한 보상과 남은 의무는 유지합니다.
- **인물별 지식 유지:** 만남 여부와 습득한 지식, 비밀의 공유 범위는 유지하고 같은 대상에 대한 반복 기록을 통합하도록 했습니다. 다른 인물의 지식이나 문서 링크를 해당 인물의 지식으로 간주하지 않습니다.
- **이전 지시문 백업:** 수정 전 기본 지시문은 `공식기본-260930`으로 선택할 수 있습니다. 기존 공식기본의 선택과 장비 및 압축 옵션은 유지하며 개인 프리셋은 변경하지 않습니다.

## [안정성] 위키·채팅·세이브의 공동 저장과 복구

- **대화와 위키의 공동 publication:** 과거 시점으로 되돌리기, 분기와 v1 세이브 불러오기는 위키 head와 전체 정본 채팅을 하나의 복구 가능한 journal 결정으로 반영합니다. 중간 저장 오류가 나면 재시작과 다음 저장 작업 전에 미완료 결정을 재생합니다. 반영 뒤 화면 저장이 실패해도 이전 대화를 다시 덮어쓰지 않습니다.
- **수동 편집의 원자적 반영:** 문서 rename과 역링크 수정 등 지원 쓰기를 staging으로 묶었습니다. 발행 전 오류는 현재 문서와 head를 그대로 유지하며, 변경 대상의 외부 편집은 보존하고 오래된 쓰기를 거부합니다.
- **과거 상태의 일관성:** 유지한 응답 경계의 체크포인트로 scriptstate를 복원하고, 대상 커밋의 조상이나 남긴 메시지에 속하지 않는 receipt와 확정 표시를 제거합니다. 필요한 과거 체크포인트가 없으면 미래 변수를 가져오는 대신 복원을 거부합니다.
- **취소와 응답 유실 처리:** journal 결정 전에는 취소할 수 있고, 결정 뒤에는 durable receipt로 실제 발행 결과를 회수합니다. 같은 operation ID의 재시도는 기존 결과를 반환합니다.
- **백업 시점 고정:** 백업 목록을 만든 뒤 정본 파일·위키·DB bytes를 임시 snapshot으로 고정하고 그 파일을 스트리밍합니다. 전송 중 새 대화나 위키 수정이 들어와도 한 백업에 서로 다른 시점이 섞이지 않습니다.
- **세이브 내구성과 이식성:** reference autosave manifest와 이름 변경은 파일·디렉터리 sync를 포함한 atomic 교체를 사용합니다. v1 세이브는 원래 이력 저장소 없이 옮겨도 내장된 전체 workspace로 복원하며, 새 채팅으로 불러오는 경로도 지원합니다.
- **분석 경계 보존:** 분석 전에 실제 정본 채팅 flush를 기다리고, 분석 도중 원본 채팅이 삭제되면 conflict로 거부합니다. 문서 변경이 없는 확정 턴도 경계 커밋과 receipt를 남깁니다.
- **분석 시작 시점 고정:** 문서 조회와 모델 호출 전에 위키 head를 고정합니다. 분석 도중 반영된 수동·외부 편집은 덮어쓰지 않고 충돌로 중단합니다.
- **분석 결과의 공동 복구:** 개별 분석 receipt를 불변 객체로 보존하고, 위키 발행 journal이 정본 채팅의 receipt·확정 상태까지 복구합니다. 첫 메시지의 분석 정보와 과거 분기에서 유효한 개별 분석은 보존하며, 미래 재분석 결과만 제외합니다. 개별 정보가 없는 이전 커밋의 부분 복원은 원래 성공 상태를 확인할 수 없어 자동 확정하지 않습니다.
- **세이브 시점 검증:** 정본 저장 완료를 기다린 뒤 저장 대상 채팅 상태와 위키 경계를 같은 저장 잠금에서 검사합니다. 사이드바 설정과 화면 임시 필드는 기존 세이브 직렬화 규칙으로 제외하면서, 오래된 메시지·스토리 변수 상태와 미래 위키를 결합한 수동·자동 세이브를 거부합니다. 자동 세이브 보관 정리에도 참조형 슬롯을 포함합니다.
- **삭제 채팅 참조 정리:** 삭제된 채팅의 마지막 복구 참조를 영구 삭제하면 남아 있던 branch pin을 제거해, 다른 참조가 없는 공유 객체를 회수합니다.
- **필수·자동 조회의 시점 통일:** 항상 포함 문서와 자동 검색·재검색은 같은 위키 commit을 사용합니다. 중간 변경은 응답 생성을 중단하며, 문서 수가 같다는 이유로 서로 다른 revision을 섞지 않습니다.

## [성능] 내부 쓰기와 외부 편집 탐지 분리

- **변경 경로 검사:** 내부 publication에서는 전체 문서 stat 순회 대신 변경 대상만 검사합니다. 이력의 background poll은 파일 감시와 주기적 전체 재검사를 사용하며, 명시적 새로고침·checkout·fork·save는 전체 캡처를 유지합니다.
- **자동 세이브 증분 저장:** 변경되지 않은 메시지 객체와 트리 노드를 재사용하고, 변경된 메시지·인덱스 경로와 작은 manifest만 기록합니다. 기존 평면 형식의 세이브도 계속 읽고 공유 객체를 보존합니다.
