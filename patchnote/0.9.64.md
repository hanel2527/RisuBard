# RisuBard v0.9.64

## [개선] 장기 채팅에서 바드위키 속도

- **위키 탭이 빨리 열림:** 턴이 수백에서 수천 개 쌓인 채팅에서 바드위키 탭을 열 때마다 모든 위키 문서를 다시 읽던 방식을 바꿨습니다. 이제 바뀐 문서만 다시 읽어서, 3,000턴 분량 위키를 서버가 준비하는 시간이 약 1초에서 0.1초로 줄었습니다. Obsidian 등에서 직접 고친 문서는 지금처럼 바로 반영됩니다.
- **턴 저장이 위키 크기와 무관해짐:** 새 사건이나 정본을 저장할 때 위키 폴더 전체를 다시 훑던 동작을 없애고, 방금 쓴 문서만 갱신합니다. 3,000턴 기준 정본 1건 저장이 0.7초에서 0.02초 안팎이 됐습니다. 위키 탭은 자동세이브가 끝날 때까지 기다리지 않습니다.
- **자동세이브는 바뀐 문서만 보관:** 세이브할 때마다 위키 전체를 복사하던 방식을 바꿔, 세이브 슬롯이 문서 목록만 갖고 내용은 캐릭터별 보관함에 한 번만 저장합니다. 두 번째 세이브부터는 그사이 바뀐 문서만 복사하므로 3,000턴 기준 자동세이브가 약 6초에서 0.2초로 줄었습니다. 불러올 때는 문서마다 손상 여부를 확인합니다. 기존 세이브는 그대로 불러올 수 있지만, 이 버전에서 만든 세이브는 이전 버전에서는 목록에 보이지 않습니다.
- **위키 탭은 목차만 먼저 받음:** 탭을 열 때 모든 문서의 본문까지 받던 방식을 바꿔, 제목과 경로 같은 목차만 받고 문서를 누르면 그 본문만 가져옵니다. 3,000턴 기준 탭을 열 때 받는 데이터가 6.5MB에서 1.4MB로 줄었습니다. 위키 검색은 서버에서 본문까지 찾아 결과만 돌려주고, `지금까지의 이야기`는 사건 요약만 받아 100개씩 표시합니다. `위키 내보내기`는 창을 열 때 전체 내용을 불러옵니다.
- **긴 폴더는 100개씩 표시:** 사건처럼 문서가 많은 폴더는 처음 100개만 보여 주고, 폴더 끝의 `100개 더 보기`로 이어서 펼칩니다. 폴더 이름 옆에 문서 수가 표시되며, 선택한 문서는 순서와 관계없이 항상 보입니다.
- **의미 검색을 켠 긴 채팅이 바로 열림:** 의미 검색(임베딩)을 켠 채팅을 새로고침하거나 다른 채팅에 다녀온 뒤 열면 저장된 벡터를 하나씩 요청하느라 위키가 30초~1분 늦게 뜨던 문제를 고쳤습니다. 벡터를 묶어서 읽고 쓰며, JSON 대신 약 5분의 1 크기의 압축 형식으로 저장합니다. 벡터 5,000개(1.4M 토큰 규모 채팅) 기준 캐시 읽기가 약 20초에서 약 1초로 줄었습니다. 기존 캐시는 처음 한 번 읽을 때 자동으로 새 형식으로 바뀌며 임베딩을 다시 만들지 않습니다.
- **오래 쓴 저장소에서 에셋 가져오기가 느려지던 문제:** 의미 검색 벡터가 공용 저장소(KV)에 수만 개씩 쌓이면, 모듈이나 봇 에셋을 하나 저장할 때마다 그 목록 전체를 다시 쓰느라 가져오기가 몇 시간씩 걸릴 수 있었습니다. 이제 벡터는 데이터 폴더의 `bardwiki-vectors`에 따로 보관하고, 기존 벡터는 업데이트 후 앱을 켜면 백그라운드에서 자동으로 옮깁니다. 벡터 2만 개 기준 에셋 하나 저장이 56ms에서 4ms로 빨라졌습니다. 옮기는 동안에도 앱은 평소대로 쓸 수 있습니다.
- **기억 회수가 위키 크기에 덜 영향받음:** 응답할 때 기억 회수는 준비된 목록으로 바로 답하고, Obsidian 등에서 직접 고친 문서 확인은 응답 뒤 백그라운드에서 해서 다음 응답부터 반영합니다.
- **위키 탭 첫 열기 미리 준비:** 채팅을 열어 두면 위키 탭을 열기 전에 서버가 위키를 미리 읽어 둡니다. 3,000턴 기준 앱 시작 직후 첫 탭 열기가 약 1초에서 0.4초로 줄었습니다.

## [개선] V3 구조 캐릭터 에셋을 캐릭터 폴더에서 읽기

- **폴더 복사본을 실제로 사용:** V3 구조로 전환한 캐릭터의 에셋은 지금까지 `characters/<캐릭터>/assets` 폴더에 복사만 되고 화면에는 공용 저장소(KV)의 원본이 쓰였습니다. 이제 폴더의 복사본을 먼저 읽습니다. 공용 저장소의 원본은 지우거나 바꾸지 않으며, 백업과 CHARX 내보내기도 그대로입니다.
- **원본과 같을 때만 사용:** 서버를 켠 뒤 처음 읽을 때 복사본 내용이 원본과 똑같은지 확인하고, 그 뒤에는 파일이 바뀌지 않았는지만 확인합니다. 파일이 없거나, 크기나 내용이 다르거나, 외부 프로그램으로 고쳐져 아직 앱에 반영되지 않았으면 오류 없이 예전처럼 원본을 씁니다.
- **문제가 생기면 끄기:** 서버를 `RISUBARD_ASSET_FOLDER_READS=0` 환경변수로 실행하면 이전처럼 원본만 읽습니다. 개발자 설정의 저장소 진단 보고서에 폴더 읽기와 원본 대체 횟수가 표시됩니다.
- **V4 시험 기능(직접 선택):** 개발자 설정의 `캐릭터 V3 저장 구조 전환`에서 V3 구조 캐릭터를 고르고 `V4로 전환`을 누르면, 그 캐릭터 전용 에셋을 공용 저장소 목록에서 빼고 폴더 복사본으로 읽습니다. 목록이 작아질수록 에셋 저장과 가져오기가 가벼워집니다. 원본 파일은 지우지 않고 보관하며 `V4 되돌리기`로 바로 복구됩니다. 다른 캐릭터, 모듈, 설정과 같이 쓰는 에셋과 폴더 복사본이 원본과 다른 에셋은 목록에 남깁니다. 백업, 내보내기와 에셋 목록에는 전과 똑같이 포함됩니다. 누르지 않으면 아무것도 바뀌지 않습니다. 이전 버전으로 돌아가기 전에는 `V4 되돌리기`를 눌러 주세요.
- **좁은 화면 넘침 수정:** 같은 설정 화면에서 캐릭터 이름이 길면 상자가 화면 밖으로 넘치던 문제를 고쳤습니다.
- **저장 구조 한눈에 보기:** 같은 설정 화면에서 캐릭터 목록 옆에 `[V3]`, `[V3 일부]`, `[V4]`가 표시되고, `전체`, `기존 구조`, `V3`, `V4` 버튼으로 걸러 볼 수 있습니다. 캐릭터 저장소의 썸네일 왼쪽 위에도 V3, V4 표시가 붙습니다. 기존 구조 캐릭터에는 아무 표시도 없습니다.
- **모듈 에셋 폴더(시험 기능, 직접 선택):** 개발자 설정의 `모듈 에셋 폴더`에서 모듈을 고르고 `에셋 폴더로 풀기`를 누르면 그 모듈의 에셋을 `modules/모듈이름/assets/`에 복사하고, 원본과 같다고 확인된 복사본에서 읽습니다. 이어서 `V4로 전환`을 누르면 다른 모듈, 캐릭터, 페르소나와 같이 쓰지 않는 에셋을 공용 저장소 목록에서 빼서 에셋 저장과 가져오기를 가볍게 합니다. 모듈 파일과 원본은 그대로이고 `V4 되돌리기`, `폴더 읽기 끄기`로 언제든 돌아갈 수 있습니다. 폴더로 푼 뒤 모듈에 새로 넣은 에셋은 `에셋 폴더 다시 풀기`를 눌러야 폴더에 들어갑니다. 에셋 수만큼 디스크와 백업 크기가 늘어납니다. 복사하는 동안에도 저장과 채팅은 평소처럼 됩니다. 모듈 에셋 9만 개 규모 저장소에서 시험했을 때 공용 목록이 29MB에서 12MB로 줄고 에셋 하나를 저장하는 시간이 약 절반이 됐습니다(에셋 2만 개 모듈 풀기 약 1분).

## [수정] AI 메타데이터 분석 화면

- **도움말이 모달 위에 표시됨:** 「AI 메타데이터 분석」 설정 항목의 `?`를 누르면 도움말이 분석 모달 밑에 깔려 보이지 않고, 버튼이 먹통인 것처럼 보이던 문제를 고쳤습니다. 이제 도움말이 분석 모달 위에 뜨고, 닫으면 원래 화면으로 돌아옵니다.
- **좁은 화면에서 상자가 찌그러지지 않음:** 폭 900px 이하(휴대폰)에서 「AI 분석 설정」과 「요청 계획」이 제목 줄만 남기고 눌려 보이던 문제를 고쳤습니다. 이제 두 상자가 내용만큼 펼쳐지고 모달 본문을 스크롤해 볼 수 있습니다. 넓은 화면의 좌우 분할과 크기 조절은 그대로입니다.

## [수정] 위키 프롬프트 블록 순서 이동 오류

- **연속 이동 가능:** 위키 프롬프트 프리셋의 `프롬프트 V2` 탭에서 블록을 선택하고 `위로 이동`이나 `아래로 이동`을 두 번 이상 누르면 `each_key_duplicate` 오류가 나던 문제를 고쳤습니다. 이제 누를 때마다 선택한 블록이 한 칸씩 이동합니다.
