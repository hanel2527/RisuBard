# RisuBard v0.9.84

## [안정성] 바드위키가 턴을 빠뜨리거나 잘라 읽지 않습니다

긴 채팅에서 바드위키가 모르는 사이에 기억을 놓치던 경로를 막았습니다.

- **턴 원문을 자르지 않음:** 지금까지는 분석 자료가 `AI 분석 토큰 상한`을 넘으면 확정된 응답의 앞부분이나 고칠 문서의 뒷부분을 잘라 AI에게 보낼 수 있었습니다. 이제 응답 원문과 고칠 문서는 항상 온전히 보내고, 상한에 맞추려고 뺄 때는 참고 문서, 로어 참고, 직전 사건 요약을 항목째 뺍니다.
- **상한의 뜻:** `AI 분석 토큰 상한`은 이제 참고 자료가 들어갈 자리를 정합니다. 기본값 8,192는 그대로이며, 상한 안에 들어가던 턴의 비용은 달라지지 않습니다. 긴 응답에서는 지금까지 잘려 버려지던 부분만큼 더 보냅니다.
- **순서대로 분석:** 분석에 실패한 턴이 있으면 그 턴부터 이야기 순서대로 다시 분석하고, 앞 턴이 끝나기 전에는 뒤 턴을 위키에 쓰지 않습니다. 실패한 턴은 직전 두 턴 안에서만 다시 시도되어 그보다 오래되면 영영 빠졌고, 늦게 다시 분석된 옛 턴이 최신 상태를 덮을 수 있었습니다.
- **밀린 턴 알림:** 분석이 멈추면 BardWiki 도크 위에 기다리는 턴 수, 멈춘 응답과 이유가 보입니다. `원문 보기`, `다시 시도`, `이 턴 건너뛰기`로 처리할 수 있으며, 건너뛴 턴은 영수증에 남습니다.
- **시간 제한 없음:** 위키 분석에 있던 10분 제한을 없앴습니다. 느린 모델도 끝까지 기다리며, `바드위키 작업 취소`로만 멈춥니다.
- **영수증에 남는 조정:** 이번 턴 정본 영수증에 분석 자료에서 뺀 항목, 상한을 넘겨 그대로 보낸 경우, 정본에서 이전 문장이 그대로 남지 않은 항목 수, 자동 정본 대상 한도를 넘어 반영하지 못한 후보가 표시됩니다.
- **같은 턴 재분석:** 일부 문서만 저장에 실패한 턴을 다시 분석할 때, 그 사이에 채팅이 이어졌어도 이미 저장한 문서는 다시 쓰지 않습니다.

## [안정성] 바드위키 정본이 갱신될 때 기존 항목을 잃지 않습니다

지금까지 정본을 갱신할 때 AI가 바뀐 절 전체를 다시 썼기 때문에, 다시 쓰면서 빠뜨린 항목은 아무 표시 없이 사라졌습니다. 수천 턴 동안 같은 인물 문서가 수백 번 갱신되면 이 손실이 쌓입니다.

- **항목 단위 편집:** AI는 기존 절의 항목에 번호가 붙은 문서를 받고, 새 항목 추가, 특정 항목 고침, 이유를 밝힌 항목 삭제만 돌려줍니다. 언급하지 않은 항목은 그대로 남습니다.
- **이유 없는 삭제는 거부:** 삭제는 이번 턴의 상태 변화로 낡았거나, 다른 항목에 합쳐졌거나, 원문으로 틀린 것이 확인된 경우만 반영합니다. 위키 링크가 함께 사라지는 삭제도 막습니다.
- **통째로 다시 써도 보존:** AI가 예전 방식으로 절 전체를 다시 쓰거나 절을 지워도, 결과 문서 어디에도 남지 않은 기존 항목은 되살립니다. 현재 상태 절과 스토리 아크 플롯은 원래대로 새로 씁니다.
- **영수증 표시:** 이번 턴 정본 영수증에 문서별로 삭제한 항목, 되살린 항목, 무시한 편집 지시 수가 남습니다.
- **정본 정리 확대:** 분량이 커진 문서를 압축하는 정본 정리가 캐릭터뿐 아니라 장소, 조직, 물건, 개념, 조사 줄기 문서에도 적용됩니다. 항목이 128개를 넘는 절도 나눠서 정리하며, 더 줄일 수 없다는 결과가 나와도 정리 기준을 높이지 않고 새 근거가 쌓이면 다시 시도합니다.
- **로어북 참고 범위:** 바드위키가 로어북에서 채우는 정보를 이름, 성별, 나이, 종족, 외모, 타고난 능력처럼 잘 바뀌지 않는 것으로 좁혔습니다. 관계, 역할, 소속, 목표, 현재 상태와 지식은 이야기에서만 가져오며, 이미 위키에 적힌 이야기 사실이 로어북보다 우선합니다.
